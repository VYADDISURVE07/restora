# Why Restora: research and reasons

*Read on 22 October 2026. Vendor features change quickly; links point to the pages used.*

**Restora repairs the request side of API tests:** missing values, wrong order and rejected calls. It works
from the sheets, Postman collections and cURL commands testers already have, with a free AI model that runs
on the tester's own computer. We found no tool that combines these.

## The gap

| Tool | What its AI does | Input it needs | Where the AI runs |
|---|---|---|---|
| [Postman Agent Mode](https://learning.postman.com/latest-v-12/docs/agent-mode/overview) | Creates and manages requests and flows, debugs errors, writes tests | Postman workspace and collections | Postman's cloud, metered by [AI credits](https://www.postman.com/pricing/) |
| [Keploy](https://keploy.io/docs/running-keploy/self-healing-ai-api-tests/) | "Fix with AI" proposes updated assertions when a response changed | Tests recorded or generated by Keploy | Keploy's AI engine |
| [Qodex](https://docs.qodex.ai/auto-healing-agent) | Patches expected responses or rules after a valid API change; [chains calls](https://docs.qodex.ai/chaining-api-calls) described in plain English | A test that passed at least once; says it does not handle failures such as missing auth headers | Qodex platform |
| [Insomnia](https://developer.konghq.com/insomnia/ai-in-insomnia/) | Generates mock servers and commit messages | A prompt, OpenAPI file or live URL | Cloud or a local model file; no test healing |
| [RESTler](https://microsoft.com/en-us/research/uploads/prod/2021/03/RESTler.pdf) | Orders calls by producer and consumer, then fuzzes | An OpenAPI (Swagger) spec | No language model |
| [AutoRestTest](https://ar5iv.labs.arxiv.org/html/2501.08600), [LlamaRestTest](https://arxiv.org/abs/2501.08598v2) | Generate input values and parameter dependencies for coverage | An OpenAPI spec | OpenAI models; a fine-tuned Llama 3 8B |
| **Restora** | Fills gaps, orders rows, heals rejected requests, explains failures | A sheet, Postman collection or cURL text; no spec | Rules first, then a free local model (Ollama) |

The commercial healers react after a test has passed once and the API later drifted. The research tools
generate new tests from a specification. Neither starts from the half-finished sheet a tester actually has.

## What is different

1. **It starts from what testers already have.** That means a CSV or Excel sheet, a Postman collection or
   cURL commands, with no spec, recorded traffic or code access. Postman collections that relied on scripts
   to pass values along still work.
2. **It repairs the request and the sequence, not only the expectation.** It fills gaps from earlier
   responses or realistic data, moves producers before consumers, heals rejected requests by reading the
   API's own error messages, and accepts values that change on every call, with a stated reason.
3. **It is private and free by design.** Rules come first, and a small open model runs on the tester's
   machine; secrets are masked even from it. Data privacy is the top generative-AI concern for 67% of quality
   teams ([World Quality Report 2025-26](https://www.capgemini.com/resources/world-quality-report-2025)).
   For Indian banks, RBI's [FREE-AI framework](https://www.lkslaw.com/insights/articles/rbi-framework-responsible-and-ethical-enablement-of-artificial-intelligence-in-financial-sector)
   (August 2025) asks for trust, accountability and AI audit mechanisms. The
   [DPDP Rules](https://www.azbpartners.com/bank/indias-digital-personal-data-protection-act-phased-rollout-and-key-compliance-milestones/)
   bring their main data duties into force in May 2027.
4. **Every decision can be reviewed, and safety rules hold.** Changes appear as tracked changes, and a
   corrected sheet records every fix. Negative tests and server errors are never healed, and secrets are
   never invented. A healed row is HEALED, not PASSED, and suggest mode verifies a fix without applying it.
5. **It checks that a negative test fails for the right reason.** "A transfer with a negative amount is
   rejected" passes in any tool that only compares status codes, even when the API refused the call because
   a header or the login token was missing and never looked at the amount. Restora reads why the request
   was refused. If the reason is a setup problem the test is not about, it fixes only that and asks again.
   A refusal now means the test checks what it says; an acceptance turns a false pass into a reported bug.
   None of the tools above describes this check.

**The local model on a gaming PC.** These are the results of `tools/ai_trial.py` with `qwen3:4b-instruct` on an
RTX 2060 (6 GB) under Windows 10, on 22 October 2026. The trial asks the model directly, including cases that the
rules would normally handle first.

| Job | Result | Time per answer |
|---|---|---|
| Values for 5 field names the rules do not know | 5 of 5 usable: purpose code, nominee relation, occupation, branch, income band. An OTP is refused without asking the model | 2.4 to 2.5 s |
| Fixes for 5 errors the rules cannot read | 3 right: UPI to NEFT, an adult date of birth, upper-case currency. 1 rightly declined: an expired session. 1 wrong: it "fixed" a NullPointerException, a case Restora's crash rule now stops before the model is asked | 3.6 to 3.9 s |
| A plain-English explanation of a UPI failure | Quotes the error code and does not invent its meaning | 3.0 s |
| Tests written from 3 plain-English requests | 2 of 3 right after Restora restores the copied call's headers and gaps: the negative-amount transfer and the unknown account type. The EUR rate test missed the currency parameter | 3.9 to 4.8 s |
| End to end: the Demo Bank plus the AI-written negative test | 6 passed, 6 healed, 1 failed (the deliberate server bug). The AI-written test was first refused only because a header was missing; Restora fixed that alone | no model calls needed |

The model's misses show why the rules come first and check everything the model suggests.

## Design choices and their grounding

* **Rules first, AI second.** Small fine-tuned models can match much larger ones at generating valid inputs
  and dependency rules ([LlamaRestTest](https://arxiv.org/abs/2501.08598v2)), and rules cover the common cases instantly.
* **Producer before consumer.** This is the ordering idea of [RESTler](https://microsoft.com/en-us/research/uploads/prod/2021/03/RESTler.pdf), applied to a sheet without a spec.
* **Read the API's error messages.** Inter-parameter dependencies cannot even be described in OpenAPI
  ([Martin-Lopez et al., 2020](https://arxiv.org/abs/2005.03320v1)), so the error message is often the only source.
* **Schema-constrained answers.** A 4B-parameter model returns valid, checkable JSON every time.
* **An instruct model, not a thinking one.** Ollama's plain `qwen3:4b` tag now points to a reasoning model that
  writes long thinking text before each answer. The instruct version answers the same small jobs in about
  3 to 5 seconds.

## Limits

Heuristics can misjudge a field name or a row's intent. A method fix after a 405 is usually right, but not
always. Multipart uploads, GraphQL-aware healing, OpenAPI import and learning across runs are not covered yet.
The open question is how much time it saves on real sheets; measuring time-to-first-green-run against a manual
baseline is the next step.
